# Kill AI Slop — 공개 프론트엔드 결과 검토 가이드

이 문서는 홈/상품/블로그/카카오싱크 랜딩 등 **사용자가 직접 보는 공개 화면**의
"Kill AI Slop" 정리 작업을 검토하기 위한 가이드입니다. 관리자 콘솔(백엔드) 작업의
`docs/kill-ai-slop-backend-review-guide.md`와 짝을 이룹니다.

이번 라운드는 색상 토큰화뿐 아니라, 지금까지 실제로 로드되지 않던 웹폰트를 로드하고
반복되는 그림자/배경/타이포 패턴을 정리해 "세련되고 미니멀한 레이아웃"을 만드는 것도
목표였습니다. 레이아웃 구조·문구·동작 로직은 건드리지 않았고, 스타일(색상·그림자·폰트·
타이포 크기)만 교체했습니다.

## 0. Phase 구성

| Phase | 내용 |
|---|---|
| 0 | Pretendard Variable 웹폰트 실제 로드(`next/font/local`) + 지나치게 작은 `h2`(카드 섹션 제목) 크기 상향 |
| 1 | auth/inquiry/reviews/header의 raw `red/green/emerald/amber` → `--success`/`--warning`/`--danger` 토큰 |
| 2 | `Card.tsx` hero `shadow-xl`, `HomeTopBanner`, 반복 배경 wash(`.page-bg-wash`), 메가메뉴 그림자 |
| 3 | 홈페이지(퀵키워드 아이콘, 골프 캘린더 배지, 블로그 카드, contact 섹션) |
| 4 | 상품 목록/상세(가격 카드, 예약 패널, 포함/불포함 탭, 캠페인 배지) |
| 5 | 블로그 카드 리스트·배경 |
| 6 | `/golf/kakao-sync` 랜딩(쿠폰 비주얼, 가격 티어, 신뢰 배지, 후기 섹션, 이모지 제거) |

## 1. 무엇이, 왜 바뀌었나

### 웹폰트 (Phase 0)
`globals.css`가 `--font-sans-fallback: "Pretendard"`를 선언했지만 실제로 폰트 파일을
로드하는 코드가 없어서, 지금까지 모든 방문자에게 시스템 폰트(맑은 고딕 등)로 렌더링되고
있었습니다. `pretendard` npm 패키지를 `next/font/local`로 self-host해서
`src/app/layout.tsx`의 `<html>` 태그에 적용했습니다. 이미 설계돼 있던 타이포 스케일
(h1 42px → body 17px → caption 13px)이 이제 실제로 의도대로 보입니다.

### 상태색 토큰화 (Phase 1, 백엔드와 동일 패턴)

| 기존 | 교체 후 | 의미 |
|---|---|---|
| `red-500/600` | `text-[var(--danger)]` | 오류 메시지 |
| `green-600`, `emerald-50/600` | `text-[var(--success)]` / `bg-[var(--success-bg)]` | 성공·완료 |
| `amber-50/100/600/700` | `text-[var(--warning)]` / `bg-[var(--warning-bg)]` | 경고·필수 안내 |
| `blue-*`(브랜드 강조) | `text-[var(--primary)]` | 브랜드 강조 |

별점(★) 표시의 `amber-500`은 **실제 평점을 나타내는 시맨틱 색**이라 의도적으로
유지했습니다(경고 의미가 아님).

### 그림자·배경·반경 (Phase 2)
- `shadow-xl`처럼 과도하게 무거운 그림자 → `--shadow-soft-strong`(카드) / `--shadow-modal`(플로팅 메뉴) 토큰
- about/blog/products/auth 등 8곳 이상에 하드코딩돼 있던 `bg-gradient-to-b from-[#f3f8ff] to-white`를
  `.page-bg-wash` 공용 유틸리티 클래스 하나로 통합

### 레이아웃 세부 (Phase 3–6)
- 홈 퀵키워드 아이콘의 그라디언트 배경 + blur + 호버 시 튀어오르는 애니메이션 제거 → 단색 아이콘 + 표준 카드 톤
- 상품 상세의 이중 보더+링 강조 박스를 accent 1개 + 얇은 보더로 단순화
- 포함/불포함 탭: 포함=success(초록), 불포함=중립 회색(경고 의미 아님이라 warning 대신 뉴트럴로 재조정)
- 상품 카드류의 프로모션 배지(`highlightLabel`)를 `productCampaignPresentation.ts`의 공용 토큰으로 통일
- 검색 자동완성의 목적지/테마/상품 카테고리 배지 — 임의의 blue/amber/emerald 구분 → 중립 톤 하나로 통일(카테고리 구분은 텍스트로 충분)
- 카카오싱크 랜딩: 다크 아트모스페릭 그라디언트(쿠폰 비주얼) → 플랫 배경 + 얇은 보더, 이모지 헤딩(🏷️🛡️💬) → Lucide 아이콘 컴포넌트로 대체, 가격 티어 박스를 브랜드 accent 톤으로 통일

## 2. 화면별 확인 체크리스트

공개 사이트는 다크모드 토글이 없으므로(라이트 모드 전용), 아래는 모두 **라이트 모드
기준**입니다.

### 전체 공통
- [ ] 페이지 로드 시 폰트가 이전보다 살짝 더 선명하고 균일하게 보이는지(맑은 고딕 느낌이 아닌지)
- [ ] 헤딩(제목)과 본문 크기 차이가 이전보다 뚜렷한지 (`ProductReviewSection`, `ProductHighlightsCard`, `ProductFeatureCard`, `RelatedProductsSection`의 섹션 제목)

### 홈 (`/`)
- [ ] 퀵키워드 아이콘 타일이 그라디언트/블러 없이 단색으로 깔끔하게 보이는지
- [ ] 골프 출발 캘린더의 프로모션 배지가 주황(warning) 톤으로 자연스러운지 (별점은 그대로 amber)
- [ ] 블로그 카드에 호버 시 확대 효과가 없어졌는지, "더올투어" 골드 텍스트가 위화감 없는지
- [ ] 최하단 문의(contact) 섹션의 버튼이 이중 카드처럼 겹쳐 보이지 않는지

### 상품 목록/상세 (`/products`, `/products/[id]`)
- [ ] 가격 카드·예약 패널의 파란 이중 테두리가 사라지고 단일 accent 톤으로 보이는지
- [ ] 포함/불포함 탭 — 포함은 초록, 불포함은 회색(주황 아님)으로 보이는지
- [ ] 상품 카드의 "추천/인기/신상품/프로모션" 배지 색이 카드 종류(홈/목록/상세)와 무관하게 일관된지
- [ ] 리뷰 섹션 평점 별, "BEST REVIEW" 배지, 골드 톤 텍스트가 자연스러운지

### 블로그 (`/blog`)
- [ ] 카드 그림자가 과하지 않은지, 호버 시 살짝 떠오르는 정도인지(급격한 확대·이동 없음)
- [ ] 배경이 다른 페이지와 동일한 톤(`.page-bg-wash`)인지

### 카카오싱크 랜딩 (`/golf/kakao-sync`)
- [ ] 쿠폰 비주얼이 어두운 후광/글로우 없이 플랫한 카드로 보이는지
- [ ] 예약 인원별 할인 가격 박스가 오렌지 그라디언트가 아닌 단색 accent + 화이트 카드로 보이는지
- [ ] "신뢰 배지"·"실제 이용 후기" 섹션 제목에 이모지 대신 아이콘이 붙어있는지
- [ ] 후기 카드의 태그 pill이 accent 톤으로 통일돼 보이는지

## 3. 이번에 의도적으로 손대지 않은 곳 (검토 시 참고)

| 항목 | 이유 |
|---|---|
| 별점(★) 표시의 `amber-500` (상품 상세, 리뷰, 카카오싱크 후기 등) | 실제 평점을 나타내는 시맨틱 색. warning 토큰으로 바꾸면 "경고"처럼 오독될 수 있어 유지 |
| `guides/*`, `explore/*`, `landings/*`(가이드·탐색·범용 랜딩 렌더러) | 이번 계획(홈/상품/블로그/카카오싱크 랜딩)의 명시 범위 밖. 스캐너 히트 다수는 기존 카드 반경 토큰에 대한 오탐 |
| 히어로 이미지 위 다크 오버레이 그라디언트(`HeroVisual.tsx`, `HomeTopBanner.tsx` 등) | 사진 위 텍스트 가독성 확보용 기능적 그라디언트로, "장식용 아트모스피어"와는 다른 목적이라 유지 |

### 별도 승인받은 카카오싱크 콘텐츠 항목 (스타일이 아닌 콘텐츠 결정)
아래 3가지는 순수 시각적 슬롭이 아니라 콘텐츠/신뢰도 문제라 별도로 여쭤봤고, **모두
현행 유지로 확정**했습니다.
- `dailySocialProofCount.ts` — KST 날짜 해시 기반 "오늘 OO명 가입" 카운터: 그대로 유지
- "1초 만에", "무제한 할인!" 등 과장 카피 톤: 그대로 유지 (전환율 목적의 랜딩페이지 카피이므로 손대지 않음)
- 익명 후기 3건(김O훈/박O숙/이O철): 실제 후기 데이터로 확인되어 그대로 유지

## 4. 재검증 방법 (선택)

```powershell
node .agents/skills/kill-ai-slop/scripts/scan.mjs src/components --exclude=admin
node .agents/skills/kill-ai-slop/scripts/scan.mjs src/app --exclude=admin --exclude=theall_manager_only
```

남은 히트는 대부분 아래 두 유형입니다.
- 이미 토큰화된 코드(`var(--...)`)를 리터럴 문자열 매칭으로 다시 잡는 스캐너 오탐
- 이번 계획 범위 밖 컴포넌트(`guides/*`, `explore/*`, 범용 `landings/*`)에 남아있는 기존 패턴

`npx tsc --noEmit -p tsconfig.json`, 변경 파일 대상 `npx eslint`, `npm run build` 모두
통과를 확인했습니다(테스트 파일의 사전 존재 타입 오류는 이번 변경과 무관).

## 5. 검토 후 알려주실 것

- [ ] 문제가 없다면 이번 라운드로 백엔드+프론트엔드 Kill AI Slop 작업을 마무리

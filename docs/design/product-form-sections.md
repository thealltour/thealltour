# 상품 등록 폼 카테고리별 구성 제안

관리자 상품 등록/수정 페이지가 한 화면에 필드가 많아 입력이 부담스러우므로, **카테고리별로 묶어서** 단계적으로 입력할 수 있게 하는 방안을 제안합니다.

---

## 현재 문제

- 상품명·한줄소개·카테고리·테마·상태·이미지·원본주소·가격·일정·가격기준·유류할증료·카드메타·옵션 JSON·설명·포인트·포함/불포함·항공편(출발/도착)·상세일정·포인트 O/X·선택관광·출발인원·약관·약관템플릿·메타SEO·노출순서·활성화·추천 등이 **한 페이지에 나열**되어 있음
- 스크롤이 길고, 어떤 블록이 필수인지·어디까지 채웠는지 한눈에 파악하기 어려움

---

## 제안 1: 아코디언(접이식) 섹션 (권장)

**개요**: 폼을 논리적인 카테고리로 나누고, 각 카테고리를 **접이식 패널**로 만듦. 필요한 섹션만 펼쳐서 입력하고, 나머지는 접어 두어 화면이 짧아 보이도록 함.

**카테고리 구성 예시**:

| 순서 | 섹션명 | 포함 필드 | 기본 상태 |
|------|--------|-----------|-----------|
| 1 | **기본 정보** | 상품명, 한 줄 소개, 카테고리, 테마, 상품 상태, 이미지 URL, 상품 원본주소 | **펼침** |
| 2 | **가격·노출** | 가격, 일정, 가격 기준 문구, 유류할증료, 카드 메타 문구, 상품 옵션(JSON), 노출순서, 활성화, 메인 추천 | 접힘 |
| 3 | **설명·포인트** | 상품 설명, 상품 포인트(혜택), 포인트 O/X(여행자보험·미팅·관광·인솔자) | 접힘 |
| 4 | **포함·불포함·선택관광** | 포함사항, 불포함사항, 선택관광 목록, 출발 인원 | 접힘 |
| 5 | **상세 일정** | 상세일정 작성 도우미(일차별), 원문 직접 편집 | 접힘 |
| 6 | **항공편** | 출발 항공편, 도착 항공편 (공항·일시·편명 등) | 접힘 |
| 7 | **약관·SEO** | 약관 템플릿 선택, 약관 및 참조사항, 약관 템플릿 관리(공통), 메타 타이틀, 메타 설명 | 접힘 |

**UX 보조**:
- 각 섹션 헤더 옆에 **필수 입력 완료 여부** 표시 (예: 필수만 채우면 ✓, 미완이면 빈 원)
- “기본 정보”만 기본 펼침, 저장 버튼은 **항상 하단 고정** 또는 폼 상단에 하나 더 두어 저장만 빠르게 가능하게
- 수정 시: 해당 상품 데이터 로드 후 **마지막으로 수정한 섹션을 기억**해 그 섹션을 펼친 상태로 시작하는 것도 선택 가능 (구현 복잡도에 따라 2차 적용)

**장점**: 한 페이지 안에서 스크롤만으로 모든 항목 접근 가능하고, 섹션 단위로 접어서 인지 부담 감소. 기존 단일 폼 구조 유지하면서 JS만으로 구현 가능.

**구현**:  
- `openSections: Set<string>` 상태로 "기본정보" | "가격노출" | … 관리  
- 각 섹션을 `<section>` + 헤더 버튼(클릭 시 openSections 토글) + 본문(openSections에 포함될 때만 표시) 구조로 렌더  
- Tailwind로 `overflow-hidden`, `max-h-0` / `max-h-[...]` 또는 `grid-rows-[0fr]` / `grid-rows-[1fr]` 트랜지션으로 접기/펼치기

## 제안 2: 탭 방식

**개요**: 상단에 **탭**을 두고, 탭 클릭 시 해당 카테고리 필드만 화면에 표시. 한 번에 하나의 카테고리만 보이므로 집중도가 높음.

**탭 구성 예시**:
- **기본** → 기본 정보(상품명·한줄·카테고리·테마·상태·이미지·원본주소)
- **가격·노출** → 가격·일정·가격기준·유류·카드메타·옵션·노출순서·활성화·추천
- **설명·포인트** → 설명·포인트 혜택·O/X
- **포함·일정** → 포함/불포함·선택관광·출발인원·상세일정
- **항공** → 출발/도착 항공편
- **약관·SEO** → 약관·메타

**UX 보조**:
- 탭에 “미완료” 뱃지(필수 미입력 시) 표시
- 저장 버튼은 탭과 무관하게 항상 노출 (전체 폼 제출)

**장점**: 화면이 단순해져 한 영역만 채우는 느낌을 줄 수 있음.  
**단점**: 다른 카테고리 값을 보려면 탭을 바꿔야 해서, “가격이랑 일정을 같이 보고 싶다” 같은 경우에는 아코디언보다 불편할 수 있음.

---

## 제안 3: 스텝 위저드

**개요**: 1단계 → 2단계 → … 식으로 **다음/이전** 버튼으로만 진행. 단계마다 해당 카테고리 필드만 표시.

**단계 예시**:
1. 기본 정보  
2. 가격·노출  
3. 설명·포인트  
4. 포함·일정  
5. 항공편  
6. 약관·SEO  
7. 확인 및 저장  

**장점**: 신규 등록 시 “순서대로만 채우면 된다”는 인지가 명확함.  
**단점**: 수정 시 “항공만 바꾸고 싶다”여도 1→2→…→5까지 이동해야 할 수 있어, **수정 UX는 아코디언/탭이 더 유리**함.

---

## 권장안 및 적용 순서

- **권장**: **제안 1 (아코디언)**  
  - 등록·수정 모두에서 “필요한 섹션만 펼쳐서” 쓰기 좋고  
  - 기존 단일 폼·단일 submit 구조를 유지한 채 **섹션만 나누면** 되므로 변경 범위가 제한적임.

**적용 순서 제안**:
1. **AdminProductManager** 내부에서 폼 필드를 위 카테고리(7개 섹션)대로 그룹화할 **배열/상수** 정의  
   - 예: `const FORM_SECTIONS = [{ id: "basic", title: "기본 정보", fields: [...] }, ...]` (필드는 실제로는 JSX 블록이므로, “어떤 블록을 어떤 섹션에 넣을지”만 매핑)
2. **섹션 헤더 + 접기/펼치기 상태** 컴포넌트(또는 인라인) 추가  
   - `openSections: Set<string>` 또는 `openSections: Record<string, boolean>`  
   - 기본값: `"basic"` 만 true
3. 기존 폼 JSX를 **섹션 단위로 감싼 뒤**, 상단에 헤더 버튼 + 본문 접기/펼치기로 교체
4. (선택) 섹션별 “필수 입력 완료” 표시 — 필수 필드만 체크해 ✓/빈 원 등 표시
5. 저장 버튼 위치는 기존처럼 폼 하단 유지 (필요 시 상단에 “저장” 버튼 하나 더 고정)

이렇게 하면 **한 페이지에 등록할 내용이 방대한 문제**를 “카테고리별로 묶어서, 펼친 것만 보이게” 하는 방식으로 완화할 수 있습니다.

원하시면 다음 단계로 **아코디언 섹션 id·제목·포함 필드 목록**을 현재 `AdminProductManager` 필드 순서에 맞춰 구체적으로 나열한 뒤, 해당 구조로 JSX를 나누는 패치 예시를 작성해 드리겠습니다.

# PR-H QA 체크리스트 — 약관·유의사항·예약조건·환불 규정 분리

PR-D ~ PR-G 구조를 운영 반영 전에 수동으로 확인합니다. 항목별로 **통과 / 실패 / 비고**를 기록하세요.

## 상품 생성 테스트

- [ ] **예약조건**(`booking_conditions`)만 입력 후 저장 → 상세 **예약 조건** 탭에만 반영
- [ ] **예약 시 유의사항**(`booking_notes`)만 입력 후 저장 → 상세 **예약 시 유의사항** 탭에만 반영
- [ ] **여행 시 유의사항**(`travel_notes`)만 입력 후 저장 → 상세 **여행 시 유의사항** 탭에만 반영
- [ ] **환불/취소 규정**(`refund_policy`)만 입력 후 저장 → 상세 **환불/취소 규정** 탭에만 반영
- [ ] 위 4개를 **모두** 입력 후 저장 → 각 탭이 **서로 다른** 문구로 표시되는지 확인

## 템플릿 테스트

- [ ] **템플릿만 선택**(본문 비움) → 해당 그룹 템플릿 본문이 상세에 표시
- [ ] **본문만 입력**(템플릿 타입 비움) → 직접 입력 본문이 표시
- [ ] **둘 다** 입력 → **직접 입력 본문이 우선**(템플릿은 무시)

## 기존 데이터 fallback (`terms_and_notes`만 있는 레거시 상품)

- [ ] `terms_and_notes`만 있고 분리 필드가 비어 있음 → 내용이 **예약 시 유의사항** 탭(또는 예약 유의 영역)에만 나타나는지 확인
- [ ] 동일 상품에서 **여행 시 유의사항** 탭에 레거시 문구가 **나오지 않음**
- [ ] **환불/취소 규정** 탭에 레거시 문구가 **나오지 않음**(비어 있으면 기본 안내 카드)

## 탭 노출 검증

- [ ] **예약 조건** 탭: `booking_conditions` 해석 결과만
- [ ] **예약 시 유의사항** 탭: `booking_notes` → 템플릿 → (허용 시) `terms_and_notes` 순 결과만
- [ ] **여행 시 유의사항** 탭: `travel_notes` → 템플릿 → 없으면 빈 값(기본 안내)
- [ ] **환불/취소 규정** 탭: `refund_policy` → 템플릿 → 없으면 빈 값(기본 안내); **다른 탭 데이터와 동일 문자열이면 개발 빌드에서 콘솔 경고**

## 관리자 미리보기

- [ ] 저장 전 미리보기에서 위 4영역이 **실제 상품 상세와 동일 규칙**으로 보이는지 확인(서버 preview API 경로)

## 모바일

- [ ] 상세 하단(또는 메인) 탭 버튼 줄바꿈·터치 영역 깨짐 없음
- [ ] 각 탭 본문 줄바꿈·스크롤 정상

## 시나리오별 스모크 (머지 전 권장)

1. 신규 상품 — 4필드 + 템플릿 조합 입력
2. 템플릿만 사용하는 상품
3. 레거시(`terms_and_notes` 중심) 상품
4. 일부 필드만 입력된 상품
5. 4필드 모두 비어 있는 상품

## 머지 조건 (PR-H)

1. 탭 간 **중복 노출** 없음  
2. **Fallback**이 정책대로 동작(예약 유의만 레거시 허용)  
3. 관리자 미리보기 ≒ 실제 상세  
4. 모바일 UI 정상  
5. 프로덕션 빌드 콘솔 **에러** 없음(개발 전용 `console.warn`은 허용)  
6. 본 체크리스트 **전 항목 통과**

## 배경

카카오 싱크 가입 후 **실제 상품 예약 퍼널**에서 유저가 **"인원수 선택 시 1인당 5만 원 × N명 할인이 즉시 적용되는 경험"**을 더 명확하게 인지할 수 있도록 UI/UX 및 계산 로직을 개선하고자 함.

### 구상 중인 핵심 정책

1. **웰컴 쿠폰팩 (첫 예약)**  
   인원수 선택 시 **1인당 5만 원 × 인원수**가 결제창에 실시간 계산되어 명확히 표기  
   (예: 4명 선택 시 **-200,000원** 즉시 차감 시각화)

2. **차기 쿠폰팩 (웰컴 사용 후)**  
   웰컴 쿠폰 소진 후에는 **1인당 3만 원 × 인원수**로 기본 혜택가가 자동 전환

현황을 파악하고 프론트엔드/백엔드 최적화 방안을 세우기 위해, 아래 관련 코드 파트의 발췌가 필요함.

---

## 발췌 요청 코드 항목

### 1. 상품 상세 / 예약 인원 선택 컴포넌트 (Frontend)

- 파일 위치 예시: `src/components/booking/*`, `src/app/tours/[id]/*`
- **요청 내용**: 유저가 예약 인원수(성인/참가자 수)를 변경할 때 상태(State)가 변경되는 영역 및 가격 계산 컴포넌트

### 2. 결제/주문 서머리 컴포넌트 (Checkout UI)

- 파일 위치 예시: `src/components/checkout/PaymentSummary.tsx` 등
- **요청 내용**: [총 상품 금액 − 쿠폰 할인 금액 = 최종 결제 금액]을 보여주는 UI 렌더링 코드

### 3. 쿠폰 할인 금액 계산 로직 (Custom Hook / Helper / Utility)

- 파일 위치 예시: `src/hooks/useCoupon.ts`, `src/utils/calculator.ts` 등
- **요청 내용**: 선택된 쿠폰과 인원수(`pax`)를 받아 최종 할인 금액을 산출하는 계산 함수

### 4. 쿠폰 데이터 구조 & 첫 예약(웰컴 쿠폰 사용 여부) 판별 로직 (Backend / API)

- **요청 내용**:
  - 쿠폰 데이터 스키마 (쿠폰 단가, 인원수 곱연산 가능 여부 필드 구조)
  - 유저가 '첫 예약(웰컴 5만 원 적용 대상)'인지 '2회차 이후(3만 원 적용 대상)'인지 판별하는 백엔드 API 또는 DB 조회 로직
